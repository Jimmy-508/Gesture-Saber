# Phase 1.3.2 手勢穩定性修正

基準 c1206d162856cea4910e4eeca9533a54ddea5a81。僅修改 Gesture-Saber。

## 原因與證據界線
舊 extendedFingers 同時要求 PIP 角度與指尖／手腕距離；任何單一條件失敗都減少計數。舊 GestureGate 把 <=1 根直接當握拳，無法辨識不可靠深度、指尖重疊與真正彎曲的差別。回歸測試重現「PIP 仍直，但指尖資料異常」低計數而非可靠握拳。姿態旋轉在理想三維資料中不會自行改變角度；實際平板究竟是深度誤差、模型丟失或配對未採用，尚無該裝置紀錄，不能斷言單一原因。

另一條路徑是模型未回傳／身分未配對不送 scene.update，導致原 BladeState 260 ms 收縮、場景 420 ms 隱藏。這些時間保留，新增逐手原因可分辨模型無手、低信心／關鍵點失效、重疊拒用、身分不符及管線無新結果。

## 修正
- 以三維 PIP/DIP 雙關節、骨鏈伸展比例、掌部尺度及明確指尖收攏證據分類；世界／影像明確矛盾為 UNKNOWN。世界座標不可靠時保守 UNKNOWN，無世界資料才使用按影像比例校正的 normalized 座標。
- 移除以低手指數收劍的 GestureGate。BladeState 統一手勢遲滯：OPEN 110 ms、FIST 80 ms。UNKNOWN 保留前態，但距最近可靠證據 700 ms 後安全收縮，需再次確認 OPEN 才重啟。
- LOST 與 UNKNOWN 分離；顯式模型／配對失敗立即停止預測、凍結最後顯示姿態並停止新增光帶。無結果 180 ms 同樣凍結。260 ms 收縮、420 ms 隱藏；握柄在最後 160 ms 淡出。既有光帶自然衰減。
- 短暫遮擋後身分可靠恢復，以既有插值橋接凍結姿態，正常追蹤的濾波參數不變。大幅身分／位置跳躍仍沿用既有安全處理。
- 500 ms 診斷刷新沿用；每手顯示原始手指數、四態、證據可靠度（啟發式比例，非 MediaPipe 機率）、理由、最近可靠手勢、中斷時間、劍狀態與隱藏原因。
- Phase 1.1 音效／合成參數、PalmPose、模型／WASM 快取及引擎池、攝影機、畫質策略不改。音效正常獨立控制，遺失速度歸零。

## 驗證
- 58 個 Node 自動化測試；以帶確定性雜訊的左右解剖模型測試垂直、水平、掌心前後、傾斜與快速位移、矛盾／塌陷骨節、握拳、UNKNOWN、短／持續 LOST、交叉遮擋與左右獨立。
- TypeScript 無錯誤，正式 Vite 建置通過；既有 Three.js 大區塊提示仍存在。
- tests/gesture-check.html 實際 WebGL 整合七項 PASS：轉平掌保持啟動、UNKNOWN 保持、短 LOST 姿態凍結、恢復、持續 LOST 單手隱藏、光帶衰減、幾何釋放。這是合成資料而非真實手部。
- 既有引擎檢查：真實 CacheStorage 命中、損壞修復、清除恢復；Worker/main 都重用同一健康引擎；空白 canvas 推論只驗證引擎，不驗收攝影機手勢。
- 原始合成音效圖、參數與資源生命週期回歸測試仍通過。

## 效能範圍
reports/phase132-cpu.json：同一桌面 Node 微基準，原計數公式（含有限值防護）平均 0.000875 ms／手，新分類 0.004664 ms／手；200 批每批 500 次，暖機 10000 次。新流程增加約 0.0038 ms／手，在雙手 24 Hz 為約 0.18 ms CPU／秒的額外成本。這不是平板、渲染 FPS、端到端延遲或 GPU 測量；不能據此宣稱平板效能改善。新增物件僅在低頻追蹤分類，渲染不建立分類資料；診斷仍 2 Hz。無新增 MediaPipe 推論。掌部姿態／音色／光帶幾何演算法不變。

## 必須實機驗收
iPad Safari、Android Chrome：自然平掌／指尖朝鏡頭／掌心前後與旋腕時不誤收；真握拳的速度；雙手交叉短遮擋與長時間離鏡；左紅右藍各自獨立；音訊與續航、平衡模式實際 FPS、推論與資料延遲。若再次消失，開診斷記錄對應手的四態、依據、中斷時間與原因（不需錄影或上傳攝影機影像）。沒有真實平板測試，因此不宣稱已通過以上項目。
