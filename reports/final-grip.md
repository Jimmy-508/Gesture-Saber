# Final Grip integration

以已部署的 `4195360527e07c1c6bb0cae2cbad51bb8afdb032` 繼續整合；保留其漏幀、反向配對及有效姿態時間修正。沒有建立另一個控制核心或新實驗 Phase。

## 正式行為

- 主控手所有有效觀測都更新同一個 `GripPose`。首次具有可信曲指平面的單手即可學到握柄穿出軸；之後隨掌部座標搬移，張掌、光刃開關及型態切換均不清除校正，不回到手掌縱向。方向不可靠時保留旋轉，位置仍更新。
- 單頭以現有 `fistEvidence()` 的三維關節／指尖證據判斷 FIST、OPEN、UNKNOWN。獨立 `BladeCommand` 只控制光刃：握拳連續 60 ms、張掌連續 80 ms，且至少兩筆；24 Hz 約需 84 ms，18 Hz 約 111 ms。UNKNOWN 及超過 125 ms 的觀測間隔會清除待確認候選，不反轉既有指令。手勢結果不阻擋姿態更新。
- 初次張掌可持有空握柄；握拳伸單刃，張掌收單刃，身分及金屬握柄保留。首次沒有可信握持軸線時保持空握柄，直到可建立軸線。
- 雙拳靠攏仍用原本的 180 ms 穩定／解除重新啟用機制。已伸刃時維持收刃 120 ms → 空柄 60 ms → 伸刃 160 ms；空柄則跳過無意義的 120 ms 收刃。共用握持軸不做額外 90° 轉向或長時間旋轉追趕。
- 雙頭鎖定後 OPEN／第二隻手離鏡不收刃。再次有效指令返回單頭後，伸刃由已確認的主控手指令決定；OPEN 可保持空柄，不會動畫結束後自動點亮。
- 舊核心回退保留舊位置／動作濾波，但也使用同一 Grip 方向及武器規則。沒有第二把武器或第二個握持估計器。

## 音效、外觀及資源

原 `audio.ts`、Phase 1.1 音色／波形／頻率／包絡、Phase 1.8 節點重用及排程門檻均未修改。只由單一武器的啟閉邊緣觸發原有聲音：有刃變形一次收劍、一次開劍；空柄合體沒有多餘收劍；返回 OPEN 單頭沒有多餘開劍。

光刃幾何、1.5 倍金屬握柄、Shader、光暈、光帶、畫質及首頁布局不變；僅更新設定內既有操作說明。模型、門檻、攝影機解析度、Worker、快取、Shader 預熱、音訊準備未改動。停止及卸載的資源釋放檢查通過。

## 最終流暢修正比較

`node benchmarks/unified-grip-replay.mjs` 使用相同雙側解剖資料、24 Hz 觀測、24 ms 送達延遲及 60 Hz 邏輯繪圖。新舊回放準備後會斷言確實處於雙頭，且每幀記錄型態。單頭方向已改變，因此**不把新舊單頭旋轉差當作延遲改善**。

| 相同高速反向／三筆漏幀案例 | Phase 1.8 | 本次整合 |
|---|---:|---:|
| 單頭／雙頭：有效觀測拒用 | 6 | 0 |
| 單頭／雙頭：輸入移動時輸出停住累計 | 416.7 ms | 66.7 ms |
| 單頭／雙頭：恢復最大位置步進 | 4.6544 | 3.0908 場景單位 |
| 雙頭：因錯誤拒用而失去型態 | 是 | 否 |

正常水平移動／轉腕的位置輸出逐幀相同；目前單頭與雙頭的 Grip 旋轉反應一致。沒有增加位置平滑、旋轉平滑或外推。恢復及急停朝有效目標單調收斂，沒有額外過衝。純三筆漏幀仍有 83.3 ms 靜止時間（舊版 150 ms）；恢復最大位置步進略增 0.0019 場景單位，因已接受的銜接完成後再反向。

觀測處理在桌面 Node 的正常單頭案例平均約 0.073 ms（舊版約 0.047 ms），P95 約 0.139 ms（舊版約 0.075 ms）；增加的是 Grip／手勢計算，不是模型推論。此小樣本桌面數據不能證明平板 FPS 改善；完整 P95／峰值及誤差見 `final-grip-comparison.json`。

舊 `phase181-comparison.json` 的準備流程可能先失去雙頭而未驗證；其雙頭旋轉結論已撤回並在舊報告註明。本次重新量測，未沿用該結論。
