# Phase 1.5.3 — 藍劍調查與診斷補強

基準：`d3b7e889f6281556044b87478388961af354964d`。本版是**診斷補強版，沒有證實藍劍延遲已修復**。沒有取得使用者平板逐手摘要，也沒有直接操作該平板。不能把合成資料、桌面 WebGL 或空白模型推論當成平板實機證據。

## 結論與證據界線

- 程式中的 Left／藍與 Right／紅共用身分配對、PalmPose、MotionFilter、預測及畫面輸出。Left 的解剖橫軸係數為 +1，Right 為 -1；使用真正鏡像、具有拇指及不同指長的骨架驗證，沒有發現某側固定多一層平滑或限速。這不能證明任意真實手勢、不同輸入品質都相等。
- 原始模型 Right → 內部 Left／藍、原始 Left → 內部 Right／紅，在輸入邊界交換一次。影片／擷取影格沒有水平翻轉；畫面位置不是手部身分。程式映射可確認，**實際操作者哪隻手對應哪個標籤仍需在裝置上單手核對**。[MediaPipe 舊版 Hands 文件](https://chuoling.github.io/mediapipe/solutions/hands.html) 說明自拍鏡像的標籤假設；[目前 Tasks Web 文件](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js) 說明 handedness 與兩種座標輸出。文件不能取代本裝置的核對，也不能證明左右手模型輸出品質相同。
- 找到的確定問題是**診斷盲點**：原 `rotationError` 比較已經過 PalmPose 保護的旋轉與畫面旋轉。若 PalmPose 已保留舊方向，這個角差仍可能很小，無法回答保護前的資料落差。原複製摘要也沒有來源、世界資料拒用原因、原始標籤分數及最新配對細節。
- 同樣劣化的關鍵點注入藍手時，藍手誤差變大；改注入紅手，劣化也轉到紅手。**輸入品質、遮擋、構圖或姿態保護較常觸發只是待驗證假設，尚未經實機證實。** 沒有證據可把平板差異直接歸因於某一行 Left 分支。

因此不任意改動藍手座標、不提高增益／預測、不移除保護、不調整共用參數，也沒有製造表面上的改善結果。藍劍較慢的實機原因仍未確認。

## 固定基準與前後比較

Node 回放：每情境 3.2 秒，24 Hz 觀測、固定 24 ms 送達、120 Hz 步進；17 種共每手 **6,528 個影格狀態**。骨架有左右解剖差異，帶確定性小雜訊；逐筆反轉模型輸出順序。涵蓋平掌、側掌、朝鏡頭、慢轉、快轉、往返、快停、90°、部分掌點失效、世界／影像矛盾、深度歧義、短遺失、交叉、交換畫面位置、低分／短暫重複標籤、零手與右手劣化對照。

紅劍每影格位置、完整 quaternion、劍尖、PalmPose 狀態／可靠度／限速、MotionFilter 速度／內部落後／預測、存在狀態／伸縮／凍結／顯示與 Phase 1.5.2 **完全一致**。藍劍也完全一致。不是只比平均 FPS 或容許較大的誤差。

## 效能與資源

沒有增加推論、解析度、AudioNode、GPU pass 或材質；每手新增兩個 240 筆 Float64 環形指標，共約 7.5 KiB，另有每手一個方向向量及場景共用暫存向量。每個姿態觀測做旗標／計數及角差，每個有效渲染影格做方向差，沒有新增每影格 Quaternion／Vector3 配置。表格及 JSON 快照仍只在設定開啟後每 500 ms／按下複製時更新。

本機 Node 往返控制迴圈平均／P95／峰值：0.010／0.038／0.119 ms → 0.012／0.046／0.245 ms。原生 WebGL 同案 CPU 提交：0.268／0.400／11.300 ms → 0.266／0.300／13.100 ms。交叉案 CPU 提交峰值 13.8 → 24.6 ms；冷啟動及其他尖峰也保留在 JSON。這是單次依序執行、受 JIT／GC／作業系統／瀏覽器排程影響的桌面測量，**不足以歸因尖峰、證明完全沒有效能退步或宣稱效能提升**。固定步進不是螢幕實際 RAF FPS，CPU 提交不等於 GPU 執行時間。需要同平板摘要比較 P95／峰值及逐手資料缺口。

## 平板下一次需要的資料

沿用「設定 → 診斷 → 複製統計摘要」。固定同一平板、平衡畫質、燈光及鏡頭位置，每次重新啟動分開採樣：

1. **實際左手單獨**慢轉／快轉／停止約 10–15 秒，出現遲鈍後複製，註明實際手別、畫面位置及出現藍劍或紅劍。
2. **實際右手單獨**相同動作與時長，再複製並註明。
3. 雙手同時約 10–15 秒，再複製。若方便，交換兩隻手所在畫面區域再做一次，避免相互遮擋。

摘要不包含攝影機影像、關鍵點或完整手部座標。停止後仍能複製最後統計，但最好在問題出現後即複製；重新啟動會重設計數。請附平板／瀏覽器版本及手部與鏡頭的大致距離。

判讀方式：觀測／有效更新間隔與缺席先分辨模型或配對缺口；來源比例／世界拒用原因分辨資料品質；原始觀測→姿態差與具體旗標分辨姿態保護；姿態→畫面差則看濾波。只有整體渲染／CPU 幀尖峰而逐手品質相同時，才調查全域負載。原始標籤 Hz 仍不是實際左右手召回率，單手核對是必要前提。這些是驗證路徑，不是已確認根因。

尚待實機：實際手別映射、紅藍輸入品質／更新率／保護頻率差異、模型零回傳與構圖關係、藍劍遲鈍的可重現原因、診斷開關的成本及同裝置渲染尖峰。**本版不聲稱通過「藍劍不再慢於紅劍」驗收。**
