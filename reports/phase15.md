# Phase 1.5 tracking core

Baseline c248fc0d777c4515d31afba193fe545cbbed880d. Only Gesture-Saber changed.

## Architecture and verified causes
Previous presence depended on wrist + multiple MCPs, a complete-palm condition, a 0.55 handedness gate for new ownership, and several weak-evidence time/distance rules. Even continuing model observations expired after 200 ms of weak evidence. Scene repeated a palm gate and had its own literal freeze/fade deadlines. Capture timestamps were incorrectly used as latest presence arrival, allowing expensive inference to age a freshly delivered observation out immediately. These are reproduced software paths, not a claim to have identified the cause of a real tablet's zero-model-output frames.

- hand-presence.ts: at least three finite, within-range normalized XY points and non-collapsed spatial spread. Depth need not be finite. No required landmark indices, palm orientation, finger shape, handedness or world-coordinate pose accuracy. Near-identical landmark sets are deduplicated (including depth when available). Out-of-range/all NaN/collapsed/too-few data cannot prove presence.
- hand-assignment.ts: model side seeds ownership (selfie convention exchanged once); position continuity with a bounded 80ms velocity projection keeps historical ownership. No score gate or weak-evidence expiry. Side mismatch is a small tie preference, not a presence rejection. History expires with the shared visibility policy. New observations without a usable side may remain present but unassigned, which is explicitly diagnosed; we do not guess a color. A single position-ambiguous observation does not keep both historical hands. Two distinct observations with ambiguous permutation retain both existing identities and freeze poses, rather than swapping red/blue or discarding both hands.
- SaberScene: consumes usable observations, updates finite position from remaining points, and preserves old direction through existing PalmPose failure/roll/depth safeguards. No PalmPose algorithm or quaternion sign changes. Pose failure does not trigger loss. Independent poseFrozen flag prevents prediction/new trail sampling while identity is ambiguous.
- tracking-state.ts + BladeState: one TRACKED / TEMPORARILY_LOST / LOST lifecycle and one 180ms stale / 260ms retract / 420ms hide policy. State controls movement permission, fade and visibility; scene has no duplicate timeout literals. Identity uses the same history visibility deadline, not a separate weak timer. Actual presence observation uses arrival time; captured time still drives motion filtering and measured data latency. No new wait or longer departure deadline.

Legacy gesture.ts is now shared types only (open field solely retained for archived benchmark fixture compatibility, ignored by live activation). Removed palm-presence helper and strong-evidence state entirely. Code is organized into separate responsibilities rather than claiming every line count decreased. Existing main screen, camera/gear, audio graph, energy ribbon, shaders, cache/engine pool and worker/main fallback are unchanged.

## Diagnostics
Settings only, 500ms rendering as before: model count -> accepted presence count and rejection reason -> established/retained identity -> updating saber or ambiguity freeze; per-hand TRACKED/TEMPORARILY_LOST/LOST plus separate pose confidence, direction and failure reason. Empty model output is explicitly distinguishable from invalid observation or unresolved identity. No permanent HUD added.

## Model boundary and risks
MediaPipe settings unchanged: CPU VIDEO, two hands, detection/presence/tracking0.55, camera target640x480/30fps, balanced target24Hz, worker with existing fallback. No evidence from actual flat-palm images to justify lowering thresholds; a blank canvas validly yields zero hands in the real engine. Zero output remains unsolved by JS and still retracts normally. Lowering all thresholds could increase false detections and has not been represented as a solution.

Accepting low-score and partial observations can retain false model positives more readily than Phase1.4.1. Minimum spatial validity, duplicate rejection, stable historical identity and conservative ambiguous-pose handling remain defenses; there is no claim of zero false identity. Continuous two-hand ambiguity can keep both sabers present but frozen only while two distinct valid observations continue. With zero/one observation, absent ownership follows normal timeout. Fast newly appearing/replacing hands, unusual crossovers and changing landmark subsets need tablet verification.

## Required real-device acceptance
Actual iPad Safari/Android front-camera flat/side/finger-toward-camera behavior, real model-zero rate, false positive/identity swap rates, crossing/reacquisition, pose continuity, audio sync, permissions/cancel/stop, balanced FPS/latency and sustained memory/thermal behavior remain unverified. Synthetic observations and blank-canvas native inference are not real tablet hand acceptance. Use the layered diagnostics to tell model-zero apart from our invalidity/identity decisions.
