# Phase 1.5.1 — 雙劍連續性與資源預備

基準：`d1881637bd3d2b19ec3868e02987abba07949e9b`。比較資料全部為本機合成回放；沒有同一平板的前後紀錄，不能宣稱藍劍實機問題已解決。

## 找到的問題與尚未確認的原因

兩劍使用同一 HandAssignment、PalmPose、MotionFilter、TrailBuffer 與渲染迴圈。左右解剖橫軸、手別映射、顏色及原始音訊聲道差異保留；未發現「Left 專用較慢渲染」分支，也未更動模型參數或增加推論。現有紀錄無法回答該平板上為何只有藍劍嚴重跳幀，不能歸因 GPU 或直接認定模型較難看見左手。

可確定並以合成資料重現的共用問題：

1. 任何未配對影格都呼叫 MotionFilter.freeze，清除線／角速度並截斷插值；漏幀較多的一手會承受較多停頓。
2. 恢復資料的位移超過 2.5 場景單位或取樣間隔超過 250 ms 時，MotionFilter 直接複製新位置／旋轉，產生不連續。
3. 音訊原本已於使用者點擊時建立完整雙聲道與兩個噪聲緩衝，揮動中沒有反覆建立節點；可改善的是每次 RAF 對相同目標重送 cancel/setTarget。
4. 光劍隱藏時未預熱 Shader，首次顯示可能遇到編譯工作；沒有平板 GPU trace 證明這是單側卡頓原因。

## 修改

- 短缺口讓既有插值完成，保留原本最多 22 ms、0.12 單位、0.12 rad 的預測；80 ms 結束預測，180 ms 凍結。身分歧義仍立即凍結，沒有延長遺失／收劍／隱藏期限。光帶不在無可靠觀測時生成新軌跡。
- 恢復資料從目前畫面姿態接回，以 32 ms 銜接，取消直接跳位。正常追蹤的速度自適應參數完全不變。姿態不可用仍可更新位置，原 PalmPose 方向／旋轉保護未改。
- 設定診斷新增每手模型標籤／有效更新 Hz、配對涵蓋率、缺席與拒用、歧義凍結及恢復、方向保護、備援與恢復、來源位置／角度突變、缺口與資料／平滑延遲。時間使用有界 240 筆環形統計，平均／P95／峰值每 500 ms 刷新；無每幀 React 更新。累計數在啟動攝影機時重設。
- 模型標籤統計在既有鏡像邊界歸屬；標籤變動會影響統計歸屬，不能當作真實左右召回率。配對涵蓋率分母包含零手結果，歧義配對計成功但不計姿態有效更新。突變門檻只是提示，不能直接斷定追蹤錯誤。
- 可複製摘要僅包含數值與模式，不含影像或關鍵點；剪貼簿不可用仍可從文字框手動複製。
- 音訊所有來源、路由、噪聲生成、Phase 1.1 頻率／濾波／增益／包絡保持原樣。雙聲道在使用者點擊攝影機後、推論前同步準備，遵守 Safari 手勢限制。不使用 OfflineAudioContext 作遊戲聲源；離線渲染只用於回歸測試。相同目標保持一秒後省略重複排程；任何變動、啟閉或停止後恢復仍送出原本自動化。
- 場景建立時利用 compileAsync 預熱原有雙劍材質，立即還原可見性，不等待它才啟動攝影機。材質／幾何／光帶持續重用，沒有增加特效或 GPU 解析度。停止／切頁仍釋放鏡頭與音訊，模型池與 SHA-256 快取維持原樣。

12 組可見光劍 renderJumps（每步 >1 單位）皆為 0，draw calls 都是 19，幾何釋放後皆為 0。場景建立 61.7–152.2 ms，編譯預熱 15.4–41.3 ms；這是同程序反覆建立場景，不能推論真正冷啟動的收益。最終 12 組實際 RAF 平均 593–1001 ms，P95／峰值約 1016–1019 ms，全部 frameTimingValid=false；即使將瀏覽器顯示為前景仍受主機節流。**這些 RAF 數據不能拿來聲稱達成 60 FPS、比較平板渲染效能或證明沒有真實掉幀**。

原生離線音訊比較使用相同亂數種子、相同三秒左右聲道啟動／穩定揮動／變速／收劍輸入，對照原版音訊圖。持續參數排程 4320→3680 次（此段輸入減少 14.8%，不代表所有遊玩場景）；最大波形差 `1.4901161e-8`、RMS 差 `1.1054433e-9`，音量 0.3 的輸出峰值 0.09490。音訊更新 CPU 平均 0.01556→0.01389 ms，P95 皆約 0.1 ms、峰值皆約 0.2 ms，計時精度不足以證明實際加速。首次建圖 6.9／6.6 ms，重用圖 unlock 皆約 0.1 ms。

這只證明回歸波形差異在門檻內，不能取代平板喇叭聽感驗收。首次音訊數值為圖與緩衝建立成本；reuse 為已備妥圖的 unlock 呼叫，並非 Safari 真實硬體 resume 延遲。音訊開／關使用同一 WebGL 回放，沒有在測試中播放喇叭聲音。

## 檢查結果

- 74 項 Node 測試通過，包含雙手對稱、左右漏幀交換、靜默送達缺口、恢復、不可靠方向仍更新位置、交叉歧義、短失蹤／離鏡、原始音訊圖逐項一致、節點重用／釋放、快取與引擎生命週期。
- TypeScript 與正式 Vite 建置通過；既有 Three.js bundle >500 kB 提示保留，無建置錯誤。
- 真實 React／WebGL 的 19 項 UI 控制檢查（包含新增逐手表格、JSON 摘要）與真實 WebGL 配合合成骨架的 19 項追蹤／光帶／音效邊緣／釋放檢查全部通過，結果見附檔。
- 真正 MediaPipe Worker ImageBitmap 推論、主執行緒 canvas 推論與故意 Worker 失敗備援初始化通過；SHA-256 模型／WASM 快取命中。推論輸入為空畫布、回傳零手，**不能證明平掌辨識成功**。
- 未修改 tracking.ts、tracker.worker.ts、HandAssignment、HandPresence、PalmPose、模型信心門檻、引擎池或快取邏輯；未新增推論／相機解析度負擔。回放後幾何資源歸零，音訊節點／Context 單次釋放測試通過；真實平板 GPU／記憶體用量尚未量測。
- 原生 Cache Storage 命中／同長度資料損壞 SHA-256 修復／清除後重取，以及 Worker／main 同一引擎重用皆通過。已快取資源下冷建引擎 Worker 368.4 ms、main 351.2 ms；重用取得各 0.2／0.1 ms，空白推論各 54.1 ms。這是單次桌面值，非平板推論速度，見 [快取記錄](phase151-cache.txt)。
- 原生離線音訊最大音量 1、雙手同時啟閉與 speed=0／8／24 三條 trace 全部無削波，最大峰值 0.39632，停止尾端 RMS=0，見 [峰值記錄](phase151-audio-peak.json)。

## 平板驗收與定位方式

同一平板以平衡模式，分別開／關音效各揮動約 15 秒，含雙手同速、左手單獨、右手單獨、交叉、平掌、短遮擋及離鏡。開啟設定→診斷→複製統計摘要，停止前或停止後保存；重新啟動會重設逐手累計。

- 如果整體幀時間 P95／峰值升高，雙手更新仍均勻：再查主執行緒／GPU 與音效開關差異。
- 若只有藍手有效間隔／拒用／歧義凍結升高：屬於單手觀測／配對更新不連續；比較原始標籤與配對資訊，不能只看 FPS。
- 若配對穩定但方向保護／姿態備援偏高：需確認角度／深度與姿態品質；目前位置仍能獨立更新。
- 模型真正零回傳的期間，不會憑空生成手；受限預測停止後依原期限凍結、收劍。這是模型與實機角度限制，不能用合成資料宣稱解決。

仍需驗收：藍劍是否不再比紅劍明顯卡頓、紅劍是否維持原表現、快速停止／恢復是否自然、原始音效聽感與 Safari 解鎖、真實雙手鏡頭／遮擋表現、持續遊玩與重複啟停的功耗及記憶體。沒有這些實機資料前，單側卡頓根因保持未確認。
