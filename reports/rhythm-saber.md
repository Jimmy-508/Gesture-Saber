# Cyberpunk Rhythm Saber

基準：`97a5e0fb85b51a5af95c834afd79bb4a54e0e11f`。新增本機音樂節奏擊破玩法，沿用主控身分、Grip Control、雙拳切換、1.5 倍握柄、原光刃／Shader／光帶、Phase 1.1 音色及音訊預備。未更動模型門檻、解析度、推論頻率、快取、Worker 備援或手勢濾波。

## 使用方式

設定 → 匯入本機音樂 → 等待分析 → 開啟攝影機並讓光劍出現 → 設定中「開始遊戲」。倒數 2.5 秒後播放；沒有歌曲仍可自由揮劍。開啟設定會自動暫停；可繼續、重新開始、停止遊戲、調音樂音量、更換或移除歌曲。歌曲結束顯示成績並可重玩。

音訊不會上傳。MP3、WAV、M4A、AAC 由裝置實際 `decodeAudioData` 能力決定；失敗明確提示。64 MB／15 分鐘，另限制解碼樣本總數；大型檔案可能需更久分析或超過裝置記憶體。只有播放按鈕需要恢復 AudioContext，匯入可在 suspended context 解碼。更換／取消會令舊解碼失效、終止舊分析 Worker、停掉舊來源，不能由遲到結果覆蓋新歌曲。

## 分析與譜面

- 非同步解碼後，分小段降採樣為 16 kHz 單聲道；每段讓出主執行緒。Worker 使用 1024 點 Hann FFT、256 點 hop，分析正向 log spectral flux、RMS、局部平均／變異門檻及起始事件強度。
- Onset 以分析窗中心標記，不以分析完成時間作節拍。160 ms 內的近鄰峰保留較強事件，不直接把所有局部峰當作目標。
- 去除 DC 的 flux 自相關估計 65–190 BPM；週期可信度不足不顯示精準 BPM。譜面始終沿用真實事件時間，不由固定 BPM 格線生成。少量可信事件採稀疏策略；缺乏明顯 onset 但持續有能量時，明示使用保守段落分布。靜音不捏造節拍，沒有可玩目標會請玩家換歌。
- 記錄每事件強度／信心與每 8 秒段落的能量、密度。設定顯示分析策略、估計 BPM／可信度、事件數、篩選後目標數與密集／稀疏段落數。
- 單刃預設相鄰目標至少 620 ms；低週期信心時至少 850 ms。密集事件優先較強代表事件。橫向每次最多移動一格（0.8 場景單位），不要求同時擊打多顆。最早事件須 ≥1.8 秒，確保完整飛行可見。

## 時鐘與移動

每事件 `travelDuration = 1.65 s`、`spawnTime = hitTime - 1.65`。固定打擊平面 `z=0`，生成於 `z=-18`：

`u = (musicTime + syncOffset - hitTime) / 1.65`

`z(t) = 18 × (0.08 × u + 0.92 × u × abs(u))`

飛行在打擊平面附近平順減速，使實際 capsule／球體接觸也有約 ±217 ms 的幾何機會（光刃位於平面時），避免名義 ±220 ms 但實際高速穿越只有數十毫秒。生成仍精確為 z=-18，hitTime 時仍精確為 z=0。

每幀直接由音樂時間求位置，完全不累加移動量。優先使用 AudioContext 輸出時間戳，否則以 context time 與可得的輸出延遲估計；另提供 ±300 ms 校正，正值提早目標。RAF 只畫畫面，不決定音樂時間。暫停記錄位置並停止來源；恢復建立新的一次性 AudioBufferSource，從相同偏移繼續。同時最多一個歌曲來源。自然結束亦等待估計的可聽輸出時間，避免輸出佇列尚未播放完便提前結算。

## 碰撞與計分

`RhythmGame` 在原場景已更新武器姿態及伸出長度後、正式 render 之前執行。使用實際 blade child 的世界矩陣，將局部 `[0,0,0] → [0,2.75,0]` 轉成世界線段；縮放、握柄、旋轉與反向後刃均已包含。光刃長度共用相同規格常數，幾何沒有改變。碰撞不是手掌或握柄的距離。

光刃 capsule 半徑 0.055、目標球半徑 0.42。先算線段最近點；連續且可信影格可用前／後線段的兩個掃掠三角面補足快速移動。端點位移 >1.5 單位、渲染間隔 ≥70 ms、身分重置、失追或恢復，不做長距離掃掠。恢復後保留 70 ms 碰撞安全期，避免重定位產生假命中；這只影響判分，未改武器追蹤。光刃未伸出及變形期間不碰撞。

同時須在 `hitTime ±220 ms` 內；遠端投影重疊不計分。±95 ms 為 Perfect +100，其餘有效接觸 Good +50；連續命中累計 Combo，過期 Miss 歸零。命中立即退出碰撞集合，只能得分一次。Miss 在通過打擊區不久即回收，不會穿過鏡頭再被擊中。

變形與判定窗口交會的事件標記為保護：沒有命中則不加分、不扣 Combo，成績記錄保護數；不移動 hitTime、不改音樂速度、不重建譜面。兩端都可碰撞，但歌曲不要求雙頭模式。

## 視覺、音效與介面

目標為共用的霓虹幾何、核心、線框及短拖尾，固定 12 個 instance 槽；碎片上限 96、每次 8 個、400 ms 消散。目標不套用遠方背景霧，以保留完整飛行過程的可見度；窄畫面依相同場景視野縮窄目標左右分布，碰撞同步使用該位置，不改光劍。沒有逐目標光源或昂貴後製，每幀重用矩陣／向量／碰撞 scratch。碎片及目標以音樂時間暫停，音樂分析不在遊玩期間執行。

擊碎聲為獨立原創短音訊 Buffer／獨立路由，與原 SaberAudio 分開；只於實際命中建立有上限的一次性播放來源，不修改原光劍的振盪器、濾波或包絡。歌曲與擊碎聲、相機／音效停止、切頁、卸載均有相應取消與釋放。

HUD 在主畫面上方置中，窄螢幕移至標題／圖示下方避免重疊；pointer-events 不攔截觸控，7 Hz UI 快照與碰撞即時迴圈分離。正式設定只保留「匯入音樂」「光劍音效」「畫面與效能」。移除原核心選擇、校正、相容模式、診斷、摘要及展示 UI，以及其 React 計時器／事件狀態。既有 localStorage 手別映射仍讀取，未校正維持原始 Right → internal Left 的既有預設。舊核心只留內部回歸能力，不再對使用者顯示。

## 驗證與限制

自動測試涵蓋可變節拍、靜音／持續音、單刃密度、音訊時鐘／暫停／重啟／來源生命週期、解碼錯誤／替換取消、前後刃／掃掠／遠端／重定位碰撞、一次計分、Miss、變形保護及既有追蹤／音效回歸。

既有 WebGL 整合頁使用真正原創 WAV、MP3 檔案，實際解碼、分析 Worker 及 AudioContext 播放，經正式 App 追蹤回呼送入合成手部資料，驗證實際命中、HUD、暫停、重玩、雙拳變形、歌曲結算、釋放。另用真實單頭／金色雙頭場景矩陣分別驗證前後刃擊碎。

這不等於真實 MediaPipe 平板玩家驗收。任意音樂的 beat／BPM 推定可能不準，尤其環境音、弱起始、速度劇變；需實際歌曲與同步滑桿校正。M4A/AAC 依裝置，尚不能宣稱所有裝置／檔案都可解碼。攝影機漏幀、遮擋及硬體音訊延遲仍存在，恢復安全期可能略過短暫命中。未量測平板 GPU/FPS 或物理端到端延遲，不宣稱新增玩法完全零效能成本。
