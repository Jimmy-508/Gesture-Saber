# Phase 1.6 — 正式手部控制核心重建

基準：`b31e5831725aa1f5c92776edb26c856f785d844e`。本次建立並接入真正獨立的新核心，正式 App 預設啟用，紅藍兩劍共用同一套新流程。保留完整 1.5.3 核心作設定中的回退，不是僅新增診斷／測試頁。

## 找到的問題與實際修改

你提供的實機數字（實際左手：藍 49／紅 143；實際右手：藍 161／紅 41）證明單手操作曾有兩個內部身分得到更新。這些合計數不能還原每個模型標籤、位置或中斷的時序，但程式分析找到可重現的一條途徑：舊配對會讓「有歷史但當下標籤相反的手」與「尚無歷史、符合當下標籤的空槽」競爭。空槽成本僅 0.05，原身分有 0.04 標籤懲罰，再加上位置預測誤差，就可能把同一觀測送去另一個顏色；兩個歷史接著又造成單觀測歧義。

本版沒有繼續在舊的 PalmPose、MotionFilter 或 HandAssignment 加條件。它們原始演算法未改；新核心是三個獨立模組：

| 模組 | 實際工作 |
|---|---|
| `control-identity.ts` | 使用模型有效觀測與時間連續性建立／維持身分，單手不與空槽競爭；雙手一對一配對。也包含共用的手別校正輸入轉換。 |
| `control-pose.ts` | 分別估計握柄位置及三維方向；方向不可靠時保留方向，位置仍更新。不含動畫追趕、旋轉速率限制或預測。 |
| `control-core.ts` | 每手一個畫面位置／quaternion，以單層指數響應銜接最新觀測；拒用過期時間戳，沒有動作外推。 |
| `scene.ts` | 新增直接控制入口；新版直接複製新核心位置與 quaternion 至既有 group。原伸縮、光帶、光暈、材質、音效回呼保留。 |
| `app.tsx` | 正式 MediaPipe 回呼預設走新核心；加入新舊切換及單手校正，沿用原攝影機 session、音訊預備與設定樣式。 |

存在驗證沿用獨立的最低資料檢查 `observeHand`／`duplicateHands`：至少三個有限、非塌陷且界內的影像點，剔除重複候選。它不是舊姿態估計或濾波。新核心完全不匯入舊 `palm-pose.ts`、`motion.ts`、`hand-assignment.ts`。

## 新版判定流程

### 身分

1. 沒有歷史時，以有限且已知的模型左右手標籤建立身分，最低手別分數 0.5；不用畫面左／右當作手別。模型本身的偵測／存在／追蹤門檻仍全部 0.55，未更動。
2. 已有一隻手、目前一份可用觀測時，優先延續原身分，不因短暫相反標籤建立另一個顏色。位移明顯不連續時暫不更新，不猜另一把劍。
3. 兩份有效觀測採一對一配對。歷史位置及有界的短時間運動趨勢只用於身分配對；不輸出成光劍位置預測。成本接近時保留身分、暫停姿態；一份歧義觀測不能維持兩隻手存在。
4. 身分歷史有效期限與既有顯示策略共用 420 ms。沒有另一套弱證據期限；真正長時間離鏡後才重新建立身分。首次模型標籤若本身錯誤，仍可能建立錯誤的初始顏色，不能從單張觀測憑空知道實際手別。

配對延續使用最高 120 ms 的位置趨勢與有限速度，單手連續性範圍 0.55 正規化影像單位；雙手配對歧義差 0.025、單觀測兩歷史歧義差 0.04。這些用途是避免交換身分，並不是額外的畫面平滑或長時間追蹤模擬。

### 位置與方向

- 握柄使用手腕與掌根中心，保留掌中心相對手腕偏移；非必要掌點短缺時仍可用手腕，手腕缺失則使用剩餘掌點及已知偏移。坐標有限且有界。
- **握柄深度改為固定互動平面 z=0**，不再將投影掌寬當成距離。平掌／側掌造成掌寬縮短不會被轉成前後位移。代價是新版不模擬握柄前後深度平移；劍身方向仍為三維。幾何尺寸及相機 FOV 保持原值。
- 世界座標的手腕至中指掌根提供指向，缺點時可使用其他仍有效掌根。長度與影像方向矛盾時使用影像備援；完全沒有可用方向時只保留旋轉，不否定手部存在。
- 保留左右解剖橫軸符號。橫軸缺失使用平行搬移的舊橫軸，不把舊橫軸投影近零的正負當成正常 90° 轉向限制。
- 正常 90° 轉腕直接接受。超過約 120° 的突然指向／掌面改變要求連續觀測確認；純深度反向仍保守保留。quaternion 正規化並維持同一半球，非有限／極端數值不進入旋轉。

### 單層畫面響應

新觀測到達前先將上一段響應取樣至當下，再以當下輸出作新起點。位置與旋轉各只有一個指數響應，沒有先過濾目標再插值再預測：旋轉時間常數約 4–18 ms、位置約 8–18 ms；較大動作使用短常數，小動作保留必要防抖，恢復時同一層使用 18 ms。沒有速度外推、角速度外推、旋轉追趕限速、預測補償或觀測之後的第二個濾波器。

新輸出直接進 Three.js group。正式 App 整合測試把舊 PalmPose.update、MotionFilter.push/sample/freeze 改成會拋錯的測試防線，雙手仍完整運作，證實不是再次穿過舊處理鏈。既有展示模式使用自己的合成動畫，不代表攝影機輸入。

啟閉沿用原 BladeState 單一政策：短暫中斷保留，180 ms 起停止不可靠動作，260 ms 收劍、420 ms 隱藏。正常追蹤首次啟動、短遮擋不重複點火、持續離鏡收劍及重新入鏡伸出維持原音效同步。

## 手別定義與回退

沒有根據合計數直接反轉原始 handedness。尚未校正時維持 1.5.3 的 raw Right → 內部 Left／藍、raw Left → 內部 Right／紅。攝影機輸入沒有水平翻轉；畫面位置不作為手別。MediaPipe [舊 Hands 文件](https://chuoling.github.io/mediapipe/solutions/hands.html) 提及鏡像標籤假設，[目前 Tasks Web 文件](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js) 列出 handedness 與坐標輸出；文件與合計數不能替這台平板完成實際手別核對。

設定 → 手部控制 → **用實際左手校正**：攝影機已啟動時，使用者只伸入實際左手，取得六份連續同標籤、分數至少 0.7 且有有效觀測的結果後，將該 raw 標籤定義為實際左手／藍劍，另一個為右手／紅劍。雙手、無手或低分會重置校正計數；可再次按鈕取消。只保存一個標籤字串於此瀏覽器，沒有影像或關鍵點。

校正共用於兩個核心；舊版只在輸入邊界正規化標籤，其原始配對、姿態與濾波演算法保留。未校正預設映射的舊路徑輸出仍精確符合 1.5.3。切換核心會重置兩手、光帶、音效啟閉、診斷與尚在途的舊觀測；維持同一攝影機與 MediaPipe 引擎。重新開頁預設仍是新核心，校正字串保留。

## 相同合成輸入的改善與代價

測試骨架有真正左右解剖差異，使用多軸方向與確定性雜訊，不是同一骨架只改標籤。17 種軌跡皆使用 24 Hz 觀測、24 ms 送達、120 Hz 畫面取樣；新舊核心接收相同資料與時間序列。合成輸入有已知真實 quaternion，與模型觀測及畫面輸出分開。全部結果見 [逐項數據](phase16-metrics.md)、[完整 JSON](phase16-comparison.json)。

**身分穩定：** 單手 80 筆觀測，帶位置往返與約三分之一錯誤標籤：

| 情境 | 舊版錯配／缺口 | 新版錯配／缺口 | 新版有效配對 |
|---|---:|---:|---:|
| 左手骨架單獨 | 26／29 | 0／0 | 80／80，同一身分 |
| 右手骨架單獨 | 22／36 | 0／0 | 80／80，同一身分 |

這是可重現的舊空槽成本競爭，不是使用者原始平板逐幀紀錄，不能把數字當成實機改善百分比。17 種雙手回放新版錯配更新皆為 0；另測試完全重疊的身分歧義，兩手保守凍結而不猜交換。

**動作反應與停止：**

| 合成指標 | 1.5.3 | 新版 |
|---|---:|---:|
| 90° 改向後，進入目標 9° 內並維持 | 100 ms | 50 ms |
| 快停後，進入目標 1° 內並維持 | 75 ms | 41.7 ms |
| 快停過衝 | 4.914° | 0.076° |
| 交叉角差 P95 | 64.544° | 8.997° |
| 部分掌點失效角差 P95 | 11.571° | 10.439° |

**不利結果也保留：** 舊版含 22 ms 受限預測，本版沒有。連續往返擬合落後 **28 → 52 ms**，慢轉 **30 → 56 ms**，快速多軸動作 **30 → 52 ms**；往返角差平均／P95／峰值 **2.682／5.915／6.756° → 4.839／8.635／9.746°**。靜止小雜訊角差約 **0.045／0.076／0.077° → 0.055／0.099／0.108°**，有輕微增加。這不是全面更快的版本，不能用身分改善掩蓋無預測的跟手代價。沒有用更長外推去追回這些數字。

改向與停止時間從已知合成事件開始，不是實機攝影機到螢幕延遲。擬合落後以 0–150 ms、2 ms 步進對齊完整 quaternion 歷史；不適合解釋所有遮擋／靜止／交叉誤差。零手回傳期間依原政策凍結／收劍，無法得知真實手的後續動作。

靜止方向抖動另以輸出 quaternion 相對平均 quaternion 的角度 RMS 量測：**0.0504° → 0.0618°**。它與上述對真實方向的絕對角差分開計算，保留了新版約 0.0114° 的合成抖動增加。

- [UI 整合](phase16-ui.json)：**21 項通過**，含首頁僅標題／兩圖示、相機啟停／取消／過期回呼、音效／品質、摘要與停止後複製。新核心只顯示適用的逐手指標；舊版保留完整既有診斷。
- [舊核心及外觀 WebGL 回歸](phase16-legacy-webgl.json)：17 種情境，紅藍位置、quaternion、劍尖、光帶及音效回呼輸入精確符合基準。靜態 298,890 像素逐通道一致、兩版均 19 draw calls，場景釋放後 geometry 皆 0。新核心的不同位置／方向不要求畫面像素相同；幾何／材質／Shader／光帶原碼完全保持。
- [真實引擎檢查](phase16-engine.txt)：Worker ImageBitmap、主執行緒 canvas、Worker 故障後備援均成功，模型／WASM／載入器快取 SHA-256 驗證通過；空白影格回傳零手。快取、引擎池與推論參數原碼未改，既有生命週期／快取測試通過。
- [原生 Phase 1.1 音效峰值](phase16-audio.json)：原正式音訊圖最大音量峰值最高約 0.3932，停止尾端 RMS 0。頻率、波形、增益、濾波與包絡原碼未改，預備與節點重用保留。新動作資料會自然改變速度驅動的聲音，並非宣稱兩核心輸出的每段波形都相同。

正式桌面 App 同時揮雙劍的 2.4 秒實際 RAF 檢查，合成觀測約 24 Hz、渲染約 60 Hz；最近一次完整量測與幀時間平均／P95／峰值記於 `phase16-app-webgl.json`。它含正式 UI、WebGL、光帶及音效，**沒有 MediaPipe 推論成本，也不是平板數據**。固定步進比較不拿來宣稱 FPS。

新控制流程每影格重用 Vector3／Quaternion，沒有新建音訊節點、GPU pass 或幾何。初始化配置兩手狀態；舊核心物件保留供回退，但新版沒有執行它們的估計／濾波。控制 CPU 的前後數據在表中，範圍不含模型推論或 GPU 執行；單次 Node 程序依序測試受 JIT／GC／排程影響，不能當作平板速度保證。沒有更改相機解析度、推論頻率、模型門檻或自適應畫質。

## 平板驗收與限制

正式網站會直接用新核心，不需進入測試頁。請在相同畫質與相同光線下，先測新版單手／雙手、慢轉／快轉／停止與交叉，再到設定切回 1.5.3 比較。若實際左手不是藍劍，先用實際左手校正，再比較；校正會同時套用新舊核心。

仍需由使用者確認：實際手別映射、首次模型標籤錯誤、平掌／側掌的模型漏幀、快速交叉身分、固定握柄深度的手感、新版無預測的連續動作代價、平板 Safari／Android 的實際幀時間與音效同步。模型完全沒有回傳觀測時，新核心也不能維持不存在的追蹤資料。**本次沒有宣稱通過平板實機驗收，也沒有宣稱所有動作都更快。**
