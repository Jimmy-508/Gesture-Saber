# Phase 1.5.2 — 旋轉反應精準優化

基準：`aea31e25d55eda2093d0f96549b279bb2a054db8`。使用者已回報 1.5.1 雙劍流暢；本次針對方向／劍尖追趕感，沒有改外觀或再建追蹤架構。

## 實際原因與修改範圍

1. **串接追趕。** 原 PalmPose 對連續姿態以 22 rad/s 限速（單次 dt 最多 65 ms），之後 MotionFilter 再 slerp 及插值。60° 快速改向在 24 Hz 的第一份觀測只能先走約 52.5°；正常可信旋轉也可能多等一筆觀測。現在可靠、間隔正常、通過既有歧義檢查的正常角度，交由 MotionFilter 負責視覺連續性。大角度仍經原方向確認，低品質與恢復仍保留原限速／0.35 rad 恢復保護。沒有把所有平滑刪除，也未單純提高限速常數。
2. **舊橫軸退化。** 在近 90° 改向時，舊橫軸幾乎平行新手指軸，投影長度近零；原程式仍比較正負，會把正常改向誤作 roll 反轉。回放會重現錯誤的出平面旋轉。現在世界座標可靠時，投影長度平方 >0.1 才作此比較；投影退化且影像／世界橫軸矛盾時，使用影像橫軸備援並降低姿態品質。正常穩定指向下的 MCP 交換、世界深度反轉、重複錯誤深度等原測試仍通過。左右使用相同條件，保留解剖橫軸符號與原鏡像邊界。
3. **旋轉與位置混合反應。** 原視覺 transition 由線位移與角度混合 speed 決定。位置原有 target 濾波、速度、transition、預測完全保留；旋轉獨立依角速度與目前角差調整 cutoff／6–24 ms 插值。正常慢轉兼顧穩定，轉動與大角差加快，超過既有 75° 證據界線的單次旋轉至少 20 ms 銜接；恢復仍為 32 ms。收到明確停止證據時 6 ms 接回，避免外推尾巴慢慢追趕。
4. **單次跳變被當成持續轉動。** 原旋轉外推會在單次 30°／60° 跳變後繼續往前，造成約 6.9°／4.1° 過衝。現在要求相鄰兩段觀測同向、角速連續且姿態可靠；恢復、反向或品質下降取消外推。旋轉 horizon 納入有界的取樣年齡，不再只從推論到達起算。仍限制 22 ms、0.12 rad、9 rad/s 與前次轉動幅度；到達後 80 ms 停止外推，180 ms 凍結，沒有延長遺失期限。

存在、身分與姿態的責任未改；hand-assignment、hand-presence、tracking、Worker、模型門檻、相機解析度、快取與引擎池均未改。此處找到的共用旋轉問題不能證明平板紅劍略順於藍劍的原因；同樣的左右鏡像輸入得到相同保護次數、誤差與延遲。實機仍須比較兩手資料品質／更新間隔。

## 方法及指標定義

`benchmarks/phase151-motion.ts`、`phase151-palm-pose.ts`、`phase151-scene.ts` 保存基準邏輯；只改匯入路徑。`node scripts/compare-rotation.mjs` 使用相同、有解剖差異的左右骨架與確定性雜訊，24 Hz 觀測、24 ms 資料送達、120 Hz 渲染步進，另有 33／60／41／80／24 ms 觀測間隔及不規則渲染步進。每條 2.4 秒，排除前 250 ms 起始誤差。此量化回放主要繞畫面 Z 軸；既有 3D 平掌、深度、腕部 roll 與多軸鏡像正確性測試另行保留，不能據此推論所有三維動作都有相同延遲改善。

11 條軌跡涵蓋慢轉、30／60／90° 改向、往返、快轉停止、小抖動、低品質、短遮擋、不同間隔與快速移動；每次同時處理雙手。部分軌跡帶握柄平移，位置與旋轉指標獨立。鏡像斷言逐案檢查雙手，不是把同一骨架只換標籤。

- rotationErrorRad 為**當下真實輸入 quaternion**與畫面 quaternion 的差；directionErrorRad 是兩者 +Y 劍身方向差，roll 對方向與劍尖的影響可分辨。
- positionError 是握柄對當下真實位置偏差。tipError 同時包含握柄與旋轉，rotationOnlyTipError 單獨計旋轉；測試使用原 tip 距離 2.75+0.12=2.87，沒有縮短劍身。單位是場景單位，不是公尺。
- bestFitLagMs 以 0–150 ms、2 ms 步進擬合輸入歷史；是合成軌跡相位指標，**不是攝影機到螢幕延遲**，也不是每個動作的逐事件反應時間。改向另量測真實改向至進入目標角度 10% 範圍的時間。
- stationaryJitterRmsRad 是靜止輸出相對平均方向的 RMS；不把慢動畫等同反應變快。falseFlips 是單步 >90° 且前 150 ms 真實方向幾乎不動的異常，abruptRotations 是 >45° 的畫面步長；後者也可能是真實快速輸入，並不直接等同錯誤。
- stopSettleMs 從**第一份可證明已停止的觀測到達**起，計回到 1° 內的時間。停止之前尚在飛行的資料不能預知玩家已停下。

[逐項平均／P95／峰值表](phase152-metrics.md)；[完整核心數據](phase152-rotation.json)；[輸入、帶雜訊觀測、PalmPose 與畫面 quaternion 分開的合成 trace](phase152-traces.json)。trace 為合成資料，不是攝影機影像或使用者手部資料。

**代價與未改善項目：** 往返角度誤差 P95 約 11.71°→12.08°，峰值 17.58°→17.66°；低品質段 P95 約 13.65°→14.83°。快速停止的未觀測期間兩版仍可能超前約 6.4°，新版沒有假裝能預知停止。大角度測試在觀測尚未到達時的角差峰值仍接近 90°；短遮擋的約 89° 峰值也未消除。快速連續移動握柄平均偏差 0.04099→0.04125，來自上游姿態改變後既有混合 speed 的微小差異；同一姿態輸入下位置濾波逐點與基準一致。沒有為了方向修改位置濾波參數。

靜止雜訊的平均角差約 0.64°→0.37°，P95 1.33°→1.23°，峰值 1.49°→1.42°，RMS 抖動亦降低。完整各案的平均／P95／峰值、劍尖、CPU、跳步與保護次數保留在 JSON，包含不利數據；不能只挑平均值宣稱全面改善。

## WebGL、效能及外觀／音效保留

`tests/rotation-check.html` 使用真正 WebGL、基準與新場景，包含 90° 改向、往返、停止、遮擋、不穩定觀測／渲染步進共十組。固定渲染步用來做相同輸入比較，**不是實際 RAF FPS 或 GPU 完成時間**。CPU 工作包括場景 update、動作／音訊回呼（無喇叭播放）、光帶與 WebGL 提交；合成骨架生成不計入。WebGL 的握柄誤差對照當次觀測目標，不是假設相機物理位置；核心 Node 比較另有真實輸入位置。

靜止相同姿態的 298,890 像素 RGBA 對照：差異通道 0、最大位元組差 0，兩版各 19 draw calls；十組回放釋放後幾何數均為 0。另有自動測試逐字比較劍長、Shader、握柄／劍身幾何、顏色與畫質／光帶邏輯。[WebGL 完整結果](phase152-webgl.json)。這不代表動態畫面相同；動態方向本來就是本次修改目標。

音效 audio.ts、dynamics.ts、光帶 trail.ts 未修改，Phase 1.1 原始圖、噪聲、音色／參數、啟閉及節點生命週期回歸保留。伸縮狀態、材質／燈光、UI 布局、Shader 預熱及音訊預備未改。只有設定原診斷表新增欄位及測試入口，不新增首頁 HUD。

新增的 Quaternion 僅在每劍 MotionFilter 建構時建立一個；每幀／每次 push 重用既有向量及 quaternion。新增五個有界 Metric／手，兩手 typed-array 額外儲存約 19,200 bytes，不隨遊玩時間增加；沒有增加 GPU 材質、網格、推論次數、相機解析度或音訊節點。診斷保持 500 ms 更新，全部摘要不含影像／關鍵點。角差換算的估計也可能包含外推超前，面板已說明不能當物理端到端延遲。
