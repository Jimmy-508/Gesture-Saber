# Gesture Saber — Phase 1.5

## 1.5 核心架構

存在（hand-presence.ts）、身分（hand-assignment.ts）、姿態（既有 PalmPose）分離。存在只要求至少3個界內有限影像點與非塌陷的空間證據，不要求指定掌部點或高信心手別。低分持續觀測不再有200ms弱證據期限；身分歧義與姿態失準可凍結動作，不能直接當作手不存在。雙手觀測皆存在時，歧義可保留兩劍；單份不明觀測不能證明兩手都在。

TRACKED／TEMPORARILY_LOST／LOST 與180／260／420ms策略集中管理，存在逾時從結果到達時間算，動作與診斷仍保留取樣時間。模型零回傳仍為模型層限制。詳細測試、風險、同程序比較與實機限制見 [Phase 1.5 報告](reports/phase15.md)。以下版本段落保留為歷史紀錄。

## 1.3.1 精準修正

- 手別只在原始、未鏡像的攝影機輸入邊界交換一次。加入雙手時序配對，避免暫時重複／交換標籤把另一隻手的姿態送進光劍；近距離重疊時保留原身分並走既有短暫失蹤機制，不猜測交換。
- 保留左右手解剖橫軸係數，修正世界／影像深度矛盾、純深度反轉與掌面退化。異常握柄旋轉不再凍結可信的手指指向；不可信姿態不做角度外推。影像備援使用攝影機實際長寬比。正常連續動作保留既有平滑與預測參數。
- 音效直接恢復 `253358f1beac6893665bfd2846c21e39168f828a` 的 `audio.ts` 與 `dynamics.ts`；只增加停止期間的非同步生命週期防護。原始振盪器、噪聲、濾波器、音高、增益、包絡及左右差異均保留。已移除 1.3 WAV、音效庫與建置生成步驟。
- 原有診斷面板每 500 ms 顯示左右手方向、姿態角度變化、備援原因及身分配對狀態；未顯示攝影機影像或骨架。

`npm test`、`npm run build` 為正式檢查。測試含完整、具有拇指及不同指長的左右手骨架鏡像、遮擋、交叉、深度反轉及 Phase 1.1 音訊圖逐項對照。引擎檢查頁可直接離線渲染目前的正式音訊圖，檢查最大音量峰值。詳細方法與實機限制見 [Phase 1.3.1 報告](reports/phase131.md)。以下 1.3／1.2／1.1 內容保留為歷史紀錄，**目前音效已恢復 Phase 1.1，即時合成，沒有使用預生成音效庫**。

- 獨立 `PalmPose` 建立右手正交基底：X 自拍鏡像、Y 向上、保留深度符號作為玩家向畫面伸劍的控制映射。局部 +Y 沿手腕至指根，左右掌法向一致；退化資料備援、突發深度／掌面反轉確認與角速度限制保護，正常連續旋轉不額外延遲。

執行 `npm test`、`npm run build`；`node scripts/compare-phase13.mjs` 產生與 1.2 相同 Node 程序的光軌 CPU 比較。引擎檢查頁新增真實快取損壞修復與引擎重用按鈕。詳細證據、離線範圍與實機限制見 [Phase 1.3 報告](reports/phase13.md)。以下 1.2／1.1 說明保留為歷史紀錄；目前快取、姿態、光軌與音效以本節為準。

## 1.2 最新變更

- 雙劍改用同一套與顏色無關的環形光軌取樣，含角度備援的劍尖殘影；低速、旋轉、停止後淡出與左右對稱皆有測試。

## 開發

需要 Node.js 24 與 npm。

```sh
npm ci
npm run dev
```

開啟終端機顯示的 `/Gesture-Saber/` 網址。本機 localhost 可用攝影機；平板必須透過 HTTPS 網站開啟，不能直接使用電腦的 HTTP 區網網址。

```sh
npm test
npm run build
npm run preview
```

`assets` 腳本從已安裝的 MediaPipe 套件複製 WASM，並下載官方 float16 v1 Hand Landmarker 模型。首次開發與 CI 建置需要網路；執行時模型、WASM、Worker 均從同一網站載入。模型約 7.8 MB；WASM 約 13 MB。沒有錄影、上傳影格或分析服務。介面使用系統字型，不需外部字型請求。

## 操作

1. 以 HTTPS 開啟，建議平板橫向，環境明亮。
2. 點擊右上攝影機圖示，允許前置鏡頭；載入中再次點擊可取消。
3. 手掌可靠入鏡即自動點亮對應光劍，不需刻意張掌。手指彎曲不影響啟閉。
4. 短暫遮擋保持狀態與凍結姿態；持續遺失後收劍，重新入鏡自動伸出。
5. 再點攝影機圖示停止；切換分頁也會停止並釋放攝影機及音訊。設定內可調整音效、畫質、全螢幕及診斷。

## Phase 1.1 攝影機診斷與備援

舊版正式 Worker 在開發環境的 Chromium 可載入並推論，無法據此重現使用者的特定 iPad 故障。確定的缺口是：攝影機與模型共用單一啟動狀態；唯一影格來源為 createImageBitmap(video)；Worker、影格轉換或推論失敗即結束，沒有相容備援。故不能聲稱已定位使用者裝置的唯一根因。

新版將 getUserMedia、video.play、首個可讀影格、模型載入及實際推論分段處理。診斷按鈕顯示各階段、模式、處理影格數、音訊狀態與故障原因。前置鏡頭使用 ideal 約束，不強制裝置無法提供的幀率。辨識用 video 元素使用 inline / muted 播放，保持極低不透明度而非 display:none、負圖層或移出視窗，避免部分瀏覽器停止解碼；攝影機影像不在遊戲中可見。

正式站點冷啟動檢查曾出現 Worker 載入逾時；在此環境量測模型完整下載約 49 秒、WASM 約 30 秒，超過舊版固定總時限（不是使用者平板的量測值）。現在以串流下載分別回報模型與 WASM 位元組進度，區分 HTTP 錯誤、下載停滯與下載後模型初始化。只在持續 20 秒沒有新進度時判定初始化停滯。模型以 buffer 傳入，WASM 透過暫時 Blob URL 載入，避免初始化時再次下載；Blob URL 在初始化完成或失敗後釋放。首次下載仍可能需要一段時間，不等同追蹤延遲。

自動相容路徑：Worker + ImageBitmap(video) → Worker + canvas 轉 ImageBitmap → 主執行緒直接 video → 主執行緒 canvas。Worker 初始化、推論或轉換失敗只切換一次主執行緒，不重複載入或並行處理多個模型。也可在設定勾選「下次啟動直接使用相容辨識模式」。主執行緒模型載入序列化，取消時會關閉晚到的模型；取消權限請求時，晚到的串流亦立即停止。

瀏覽器測試曾確認：主執行緒不能使用與 Worker 相同的 ESM WASM glue，否則會出現 ModuleFactory not set。現在 Worker 使用 module loader，文件環境使用 classic loader，兩者均經正式建置推論檢查。

## 視覺與原創合成音效

光劍採 3D 圓弧收尖核心、細微能量流動 shader，以及依鏡頭與劍軸調整方向、徑向衰減的光暈；不使用全畫面 bloom。握柄重新建立金屬環境反射、粗糙深色握區、機械接縫、按鈕及 LED。光軌使用預配置緩衝，依劍尖位置與方向採樣、補間，逐樣本按時間淡出，超過位移門檻會切斷以避免跨畫面破面。低畫質仍保留核心與光暈，減少像素比、光軌壽命並關閉劍身點光源。

音效由 Web Audio 即時合成：每把劍各自的持續振盪器、過濾噪聲與啟閉音高掃頻，不使用電影或遊戲音效素材。可靠手部入鏡同步伸展和啟動聲，持續追蹤遺失同步收縮和收束聲。追蹤更新時計算完整劍尖位移速度（含旋轉），連續控制音高、音量、低通頻率及破風噪聲；靜止不播放破風聲。開關及音量在設定中調整。AudioContext 只在點擊開始、展示或啟用音效時建立／恢復；結束、切分頁及卸載時停止聲源、斷開節點並關閉 context。

## 檢查

`npm test` 包含攝影機權限錯誤、video 播放失敗、前置鏡頭要求、串流晚到、資源釋放、Worker 初始化與推論故障、主執行緒切換與單影格排程、左右獨立伸縮、短暫失蹤、速度音效映射、連續聲源與音訊釋放。Web Audio 單元測試使用替身節點，不能驗證裝置實際聽感。

正式建置提供 `/Gesture-Saber/tests/engine-check.html`，手動點擊後以空白 canvas 檢查 Worker 實際模型載入／推論、主執行緒實際模型載入／推論，以及注入 Worker 初始化失敗後的備援。它不要求攝影機，不能當作實機雙手驗收。這個頁面和正式遊戲均由同一 Vite build 產生。

## GitHub Pages

儲存庫名稱應為 `Gesture-Saber`。`vite.config.ts` 的 base 為 `/Gesture-Saber/`，Worker 與模型路徑均使用此 base。

在儲存庫 Settings → Pages → Source 選擇 **GitHub Actions**。推送 main 後 `.github/workflows/deploy.yml` 執行 npm ci、手勢測試、TypeScript 檢查、正式建置與 Pages 部署。Actions deployment 的 page_url 才是已確認的測試網址。變更儲存庫名稱需同步調整 base。

## 驗收與限制

瀏覽器可驗證展示、音訊啟用狀態、設定、錯誤狀態及引擎檢查頁；真實雙手、左右標籤、握拳、轉掌、快速揮動、交叉遮擋、音效聽感及長時間效能仍需用 iPad / Android 前置攝影機實測。

實機清單：HTTPS 開啟 → 允許權限 → 左手藍 / 右手紅 → 可靠入鏡自動啟動 / 離鏡自動收劍 → 轉掌方向 → 快揮光軌 → 離鏡隱藏 → 分頁暫停 / 重新啟動 → 三種畫質 → 橫向及直向排版。沒有實測資料前，不能聲稱通過平板流暢度或低延遲驗收。

MediaPipe 參考：[官方 Web 指南](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)。手別標籤按照模型對鏡像輸入的慣例，對原始攝影機畫面交換左右；畫面位置再鏡像一次以符合自拍直覺。
